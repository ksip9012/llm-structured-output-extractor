# 0004. 自動テストでは LLM 応答をモック（記録済みfixture）にする

- Status: Accepted
- Date: 2026-09-27

## Context
本プロジェクトは Gemini API（[0003](./0003-use-gemini-for-structured-output.md)）への
実 API 呼び出しを含む。pytest / CI で毎回実 API を叩くと、費用・非決定性（応答内容が
毎回変わりうる）・API障害時のテスト失敗・実行速度の低下といった問題が生じる。

比較検討として「ローカル LLM（Ollama等）を構築してテストに使う」案も検討したが、
以下の理由で採用しなかった:
- 本プロジェクトの検証対象はあくまで「選定した Gemini API の Structured Output 機能が
  正しく機能するか」であり、別モデル（ローカルLLM）で代替すると検証の意味が変わってしまう
- ローカルLLM構築は今後のLLM開発全般に向けたインフラ投資であり、Step1-A2単体のテスト目的
  には過剰。必要になれば独立したトピックとして別途検討する

## Decision
自動テスト（pytest）では、事前に実際の Gemini API から取得した応答を記録した
fixture をモックとして使い、実APIは呼ばない。
記録済みfixtureの更新・実API疎通確認は、`--run-llm` 等のオプトインフラグを付けた
別カテゴリの統合テストとして分離し、通常の `pytest` 実行では走らせない。

## Consequences
- 通常のテストは無料・高速・決定的になり、CIにも組み込みやすい
- 記録済みfixtureはAPI仕様変更・モデル更新時に陳腐化しうるため、定期的な更新が必要
- 実APIとの疎通確認テストは手動実行が基本となり、CIでは既定でスキップされる
